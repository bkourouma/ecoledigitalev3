# Internationalisation (next-intl, sans préfixe d'URL)

Le web utilise `next-intl` en mode **sans routage par locale** : les URL ne changent jamais (`/tableau-de-bord`,
pas `/fr/tableau-de-bord`). La locale est fixe — `fr-CI` — et la structure est prête pour d'autres langues.

## Où est quoi

| Fichier | Rôle |
|---------|------|
| `messages/fr-CI.json` | Catalogue de la locale `fr-CI` (namespaces : `common`, `actions`, `errors`, `emptyStates`, `navigation`, `pwa`) |
| `src/platform/i18n/config.ts` | Locales supportées, locale par défaut, `resolveLocale()` (seul point à modifier pour une locale dynamique) |
| `src/platform/i18n/messages.ts` | Table `locale -> catalogue` |
| `src/platform/i18n/IntlProvider.tsx` | Fournisseur pour les composants clients (branché dans `src/app/providers.tsx`) |
| `src/platform/i18n/request.ts` | Configuration serveur (`getTranslations`, `getMessages` dans les server components), référencée par `next.config.js` |

Les pages existantes ne sont pas modifiées : tant qu'une page n'appelle pas `useTranslations`, rien ne change.

## Utiliser les traductions

Composant client :

```tsx
"use client";
import { useTranslations } from "next-intl";

export function SaveButton() {
  const t = useTranslations("actions");
  return <button>{t("save")}</button>;
}
```

Server component :

```tsx
import { getTranslations } from "next-intl/server";

export default async function Page() {
  const t = await getTranslations("emptyStates");
  return <p>{t("noStudents")}</p>;
}
```

Valeurs dynamiques : `t("greeting", { name })` avec `"greeting": "Bonjour {name}"` dans le JSON.

## Ajouter une clé

1. Ajouter la clé dans `messages/fr-CI.json` (sous le bon namespace, texte français).
2. Elle est typée côté TypeScript via l'import JSON ; le test `i18n.test.tsx` vérifie qu'aucune valeur n'est vide.

## Ajouter une langue (ex. `en`)

1. `src/platform/i18n/config.ts` : ajouter `"en"` à `LOCALES`.
2. Créer `messages/en.json` avec **exactement les mêmes clés** que `fr-CI.json` (le test `i18n.test.tsx` échoue sinon).
3. `src/platform/i18n/messages.ts` : importer le fichier et l'ajouter à `CATALOGS`.
4. Décider d'où vient la locale (préférence utilisateur, profil du tenant, cookie) et l'implémenter dans
   `resolveLocale()` / `request.ts` — **jamais** par un préfixe d'URL.

## Règles

- Les textes d'interface passent par les catalogues ; pas de nouveau texte français en dur dans un composant migré.
- Les clés sont stables et décrivent le sens (`errors.network`), pas le texte.
- Dates, nombres et montants : `useFormatter()` de next-intl (fuseau `Africa/Abidjan`), jamais de formatage manuel.
- Les messages d'erreur de l'API (`{ code, message }`) restent la source de vérité pour les erreurs métier ;
  `errors.*` ne sert qu'aux erreurs techniques du client (réseau, délai, session).
